# 谁会爆炸（Who Will BOOM）

[在线试玩](https://bishop-zh.github.io/who-will-boom/) · [WebGL 构建与发布](WEBGL.md)

网页为单机 / 三名 AI 试玩版；局域网联机、TCP/UDP 语音保留在 Windows 桌面版。


《谁会爆炸》是一款以“概率会过期”为核心的多人回合制扫雷博弈游戏。玩家围坐在酒馆里，根据格子的公开风险信息选择翻格、插旗或使用道具；真实爆炸概率会随回合发生隐藏变化，因此看起来安全的信息未必一直可靠。游戏支持单人对抗 AI，也支持房主建房、其他玩家加入的联机对局。

> 项目仍在迭代。下面描述的是当前仓库已有的实现；不同设备上的界面、语音和网络体验仍需实际测试。

## 玩法与功能

- **概率扫雷**：每格分别保存真实风险和对玩家显示的风险。翻格时按真实风险结算；踩中爆炸会消耗机会，机会用尽后出局。格子可插旗，风险场可配置安全区、风险簇和开局信息。
- **信息漂移**：回合推进后，未翻开的格子可发生隐藏的概率变化，而屏幕上的旧读数不会自动同步更新。探查、扫描等道具可以重新获取局部信息；降险、增险、护盾、冻结漂移、换手等道具改变博弈节奏。赤雾喷罐可提高九宫格风险；菱域扰动器可让空心菱形的 12 格大幅升险或降险。共用地图上的效果对所有玩家生效。
- **回合与胜负**：最多四个座位，支持操作限时、AI 补位、对局结束排名，以及返回大厅、再来一局等流程。创建游戏时可以在二级界面设置地图大小、炸弹数量、概率偏移和回合限时。
- **单人与联机**：单人模式由 AI 补齐空位；联机采用房主主持对局，客户端提交操作并接收权威状态快照。玩家断线或退出后，其座位可交给 AI，重连时再交还给真人。局域网可扫描房间，也可手动输入地址和端口；通过能够转发 TCP 的网络工具也可连接。
- **场景与界面**：主菜单直接展示真实酒馆场景和 AI 演示对局；游戏内提供角色、平板盘面、等待连接、设置和结算界面。首次启动会弹出完整规则教程，之后可从主菜单或对局内设置再次打开。界面由 UGUI 和 TextMeshPro 构建，按窗口尺寸及安全区调整布局。
- **音频**：有背景音乐、事件音效、按钮反馈和座位语音。语音跟随角色位置播放，并驱动说话状态表现。

## 技术实现

| 领域 | 当前方案 |
| --- | --- |
| 引擎与语言 | Unity **2022.3.62f3c1**、C#；目前使用 Unity 内置渲染管线 |
| 界面 | UGUI、TextMeshPro、`CanvasScaler` 与安全区适配 |
| 规则 | `GameSession` 管理回合、玩家、道具和事件；`RiskBoard` 管理每格真实/显示风险；ScriptableObject 保存难度、漂移、道具等配置 |
| AI | `BotBrain` 根据风险、道具和局面选择指令；空位与离线座位可由 AI 接管 |
| 联机 | `TcpLanTransport` 在后台线程处理 TCP 收发，主线程派发消息；房主验证操作，并向客户端发送按座位裁剪的状态快照 |
| 音频 | Unity 麦克风采集、16 kHz 单声道 16 位 PCM、TCP 中继或局域网 UDP 广播、`OnAudioFilterRead` 实时回放 |

规则层使用固定种子和指令驱动状态变化，便于复现一局对局；联机运行时以**房主下发的权威快照**作为客户端状态来源，私人盘面和私人探查信息只发给对应玩家。这也避免客户端自行推进 AI 或规则而与房主产生分歧。

## 语音为什么不容易“说一句丢半句”

早期语音最容易出现的断续，不一定是网络丢包：如果每一帧只读取麦克风此刻的一小段，再把读取位置直接跳到最新位置，渲染帧间采到的样本就会被跳过。当前实现把**采集、发送和播放**分开处理：

1. **按采样位置连续读取**：麦克风使用循环录制缓冲。发送端比较本次与上次的采样位置，处理缓冲回绕，并按顺序取出所有完整的音频帧。当前固定为 **16 kHz、单声道、每帧 20 ms（320 个采样点）**；不足一帧的尾部留到下次，不因画面帧率波动而直接丢弃。若主线程停顿导致积压超过约 500 ms，才主动丢弃过旧片段，以免语音延迟无限增长。
2. **保护句首和句尾**：默认按住 **V** 说话，此时按键本身就是发送许可，低音量音节也会发送，不再被语音活动检测误删。可切换自动声控；该模式按环境噪声估计门限，使用连续片段确认起音、约 120 ms 的预录缓冲保留句首，并至少保持约 400 ms 的句尾拖尾，减少轻声字和短暂停顿被切断的机会。
3. **接收端平滑网络抖动**：每个座位有独立的环形播放缓冲，默认先积累约 **100 ms** 再播放。缓冲上限约 **400 ms**；积压过多时丢最旧的数据，控制实时通话延迟。音频线程按输出设备采样率对 16 kHz PCM 做线性插值，避免音调/速度异常；重新起音和欠载时做短暂淡入或衰减，减轻突兀的爆音。
4. **选择可到达的通道**：联机时默认将语音与游戏消息一起通过房主的 **TCP 中继**发送，适用于仅转发一个 TCP 端口的连接方式；局域网模式也提供 UDP 广播。房主根据连接确认语音所属座位，再转发给其他玩家。设置界面另有仅在本机录制并回放的麦克风测试，测试录音不会送到房间。

这些措施主要解决**本机采样跳读、声控截字和一般网络抖动**。它们不能保证任何网络条件下都完全不断音：目前传输的是未压缩 PCM，TCP 与游戏消息共用连接，严重拥塞会增加延迟；UDP 丢包也没有 Opus 等编解码器的丢包隐藏。若后续需要大规模或公网低延迟语音，可再考虑独立语音通道、编码压缩、序号/时间戳和自适应抖动缓冲。这里不把这些未来方案写成已实现功能。

## 获取与构建

1. 使用 **Unity 2022.3.62f3c1** 打开仓库根目录，等待资源导入完成。
2. 在编辑器中打开 `Assets/Scenes/BombTavern_Play.unity`，或通过菜单 **工具 → 炸弹酒馆 → 7. 构建 Windows 独立版** 构建 Windows 64 位播放器。
3. 构建脚本位于 `Assets/Editor/Game/PlayerBuilder.cs`；当前脚本输出目录是 `Build/WhoWillBOOM_2026-10-09/`。交付压缩包另外使用日期和中文修改内容命名。`Build/` 是本地构建产物，不随 Git 提交。也可使用命令行 `-executeMethod BombTavern.EditorTools.PlayerBuilder.BuildWindows` 构建。
4. 联机时由一位玩家建房，其他玩家在主菜单加入。默认游戏端口为 **7788/TCP**；局域网 UDP 语音模式使用游戏端口加一。使用网络穿透工具时请转发实际设置的 TCP 端口，并在客户端填写可到达的主机地址。

主要源码位于 `Assets/Scripts/Game/`：`Core/` 是规则与盘面，`AI/` 是机器人决策，`Net/` 是联机协议与传输，`Runtime/` 是场景驱动、界面、语音和音效，`Config/` 是可配置数据定义。

## 战绩统计与界面微调

主页“战绩统计”展示本机完成对局的总数、胜场、胜率、最高连胜、近期十局和单人/多人分布。点击近期记录可查看模式、结束时间、玩家昵称、回合数、翻格、踩雷和道具使用次数。统计由 `GameDirector` 观察实际对局结束状态：菜单 AI 演示、AI 座位及只收到已结束快照的晚到观战者不计入，同一局只保存一次；提前退出未完成对局也不计入。

历史保存在 `Application.persistentDataPath/match-statistics-v1.json`，关闭游戏后保留。临时文件完成后原子替换主记录，并保留备份；读取到损坏主文件时尝试备份，两者都损坏时保留原文件并显示错误，不用空历史覆盖。累计总数独立保存，最多保留1000场详情，弹窗展示最近10场。旧版本没有保存的历史无法还原，新版从首次完成对局起累计。

图表使用原生 UGUI：`StatisticsRingGraphic` 继承 `MaskableGraphic`，通过 `OnPopulateMesh(VertexHelper)` 按胜率划分环形几何；模式比例条用 `Image.Type.Filled` 的 `fillAmount` 更新。因此图表反映实际记录，可以在预制体中调整环宽、颜色和布局，无需外部图表插件。API 依据见 [Unity 网格生成说明](https://docs.unity3d.com/cn/2019.2/ScriptReference/UI.Graphic.OnPopulateMesh.html) 和 [Filled Image 说明](https://docs.unity3d.com/cn/2019.2/ScriptReference/UI.Image.Type.Filled.html)。

八个页面预制体集中在 `Assets/Resources/BombTavern/Prefabs/UI/`：主页、游戏说明、设置、开始游戏二级页、创建对局规则、对局结束、等待连接和战绩统计。编辑器创建菜单只补建缺失文件；微调注意功能节点和布局组的约束，详见 `Docs/UI预制体调整说明.md`。

设置页沿用在 Sprite Editor 手工保存的独立标题、主框及控件切片，重新拼装时不覆盖图集切片记录。主页与对局内共用此预制体；对局规则、结算和等待连接页统一使用现有金色边框与深棕底板。后台验证和未测范围见 `Docs/设置重拼与界面风格统一验收_2026-10-09.md`。
