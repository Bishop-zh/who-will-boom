# UI 后台验收与修复记录（2026-10-09）

本轮全程使用隐藏的 Unity batch 图形播放器，未激活前台窗口，未发送操作系统鼠标或键盘输入。检查最近制作的主页、游戏说明、开始游戏二级页、创建规则、战绩提示和主页/对局共用设置弹窗。检查结论只适用于下面列出的后台 UI 范围。

## 本轮修复

- 二级页在 Canvas 尺寸稳定后计算缩放，并监听安全区尺寸变化；避免刚打开时左右面板过小。
- 四个角色都有选中和未选中边框。首次默认第一位，返回主页再进入保留刚才选择。
- 修正联机端口输入框的锚点，缩短加入说明，消除说明、地址和端口之间的重叠。
- 滑条轨道和手柄启用射线命中；缩短轨道，避免 100% 数值被手柄挡住。
- 显示、音频和辅助功能页分别为固定底栏留出空间。移除普通按钮上的下拉箭头；仅真正下拉框保留箭头。
- 教程预制体根节点提升到设置遮罩前方，使关闭按钮和滚动区可用；改善小提示纸条的文字对比。
- 设置和教程淡出期间保留遮罩。对局设置完全隐藏后才解除第一人称输入锁，避免可见弹窗尚未关闭就误点牌桌。
- 分辨率与窗口模式文案显示实际 Screen 状态，分辨率变化后刷新文案。

修改已保存到项目内的 SettingsPopup、StartGameSetup 和 RulesTutorial 预制体及相关脚本。

每轮取得 18 张有效截图，共 72 张。batch 交换链直接截图曾出现黑帧，因此最终使用同一实时场景及 UGUI 的 RenderTexture 离屏渲染。每张图都核对可见 Overlay Canvas 内按钮转换前后的矩形位置，最大偏差在报告显示精度下为 0.000 px，均小于 1 px。禁用的 HUD Canvas 不参与核对，世界空间 Canvas 不做此转换。

逐图检查了角色边框、面板尺寸、地址/端口行、下拉列表、滑条数值、页脚和弹窗层级；GPT-6 Sol 中度思考的独立陪审也复看了四种尺寸的关键截图，确认前轮遮挡已消除，当前后台 UI 范围可交付。

原始 TMP 布局遥测每轮仍记录 118 个 overflow 标志，主要是装饰箭头、标题行高等；这些不是 104 项检查中的排版失败计数。截图未见相应文字截断，滚动区外的详细内容由视口裁切。不能将通过数量解释为所有文字边界自动断言都通过。

计时从射线命中之后发送事件开始，到状态条件成立及下一次 Canvas 刷新结束；不含实际鼠标硬件、操作系统输入队列、显示器刷新。后台程序回调未见超时，以上数字不代表玩家感知的完整输入延迟。

## 证据与复跑

每个目录有 18 张 PNG、ui-tests.json，播放器日志位于相邻同名 .log：

- `Build/UIAcceptance/accepted-1280x720`
- `Build/UIAcceptance/accepted-1600x900`
- `Build/UIAcceptance/accepted-1920x1080`
- `Build/UIAcceptance/accepted-1600x1200`

最终构建日志：`Build/ui-acceptance-release-build.log`。可执行文件：`Build/WhoWillBOOM_2026-10-09/BombTavern.exe`。

后台复跑示例（需要在隐藏进程中启动，不要去掉 batchmode）：

```text
BombTavern.exe -batchmode -screen-fullscreen 0 -screen-width 1600 -screen-height 900 -btUiAcceptance "验收输出目录" -logFile "验收日志.log"
```

验收探针只在存在 -btUiAcceptance 参数时安装；正常打开游戏不会自动运行测试。测试会暂存并恢复它修改的项目 PlayerPrefs 设置，测试期间暂停声音，也不访问真实麦克风。
